# 交付组织：四角色协作机制

> 本文件定义本项目 P6–P11 推进阶段的角色分工、交接物与验收门。
> 目的不是形式主义，而是**让"做完"这件事有独立判定者**——本仓库已经吃过一次
> 「5 个 Sprint 的验收要求被系统性跳过」的教训（见 `design-conformance-review-2026-09-23.md`）。

---

## 一、角色定义

| 角色 | 代号 | 唯一职责 | 禁止事项 |
| --- | --- | --- | --- |
| **总管** | `lead` | 决定批次顺序与范围边界；把关是否越出 V3.0 设计；维护基线不被破坏（`baseline.md` 的锁定项）；提交与打 tag；对未完成项如实上报 | 不得自行放宽验收门；不得为了让批次"通过"而修改验收标准 |
| **提示词工程师** | `spec` | 把 V3.0 设计原文 + 现有代码约定，翻译成**可执行的施工规格**（模型字段表、端点表、测试用例表、迁移影响、权限点）；规格必须逐条可回溯到设计行号 | 不得发明设计里没有的业务规则；不得编造政策金额、退费口径、政府字段 |
| **执行** | `build` | 按规格写代码：模型、迁移、服务、端点、测试、前端页面；每步保持 `pytest` + `ruff` 全绿 | 不得跳过测试；不得用前端按钮禁用代替数据库约束；不得引入设计禁止的组件（PostgreSQL/Redis/Celery 等） |
| **验证** | `verify` | **独立**复核：跑全量测试与静态检查；对照 `acceptance-checklist.md` 逐条勾选；主动找漏项、找"看起来通过实际没验"的假阳性；报告与执行者结论不一致时必须给出证据 | 不得替执行者改代码（保持独立性）；不得只看执行者的自述就签字 |

**核心约束：验证与执行必须是不同主体。** 自己验证自己等于没验证——这正是本项目历史问题的根源。

---

## 二、批次推进协议（每个批次必须走完七步）

```
1. spec    → 产出 specs/P<n>-<sub>.md（施工规格）
2. lead    → 复核规格：是否越界？是否可回溯设计？→ 批准
3. build   → 按规格施工
4. build   → 自检：pytest / ruff check / ruff format --check 全绿
5. verify  → 独立复核 + 对照 acceptance-checklist 逐条勾选
6. lead    → 回写 acceptance-checklist.md 与批次记录；git commit
7. lead    → git tag 锚定（批次的原子性边界）
```

**任何一步失败，退回上一步，不得降级通过。**
批次必须**小到可以一次验收**——宁可多个小批次，不要一个巨大批次做不完。

---

## 三、批次原子性规则（防止半成品）

1. **一个批次 = 一个 commit + 一个 tag。** 中断时不得留下"改了模型没写迁移"或"写了端点没写测试"的中间态。
2. **模型与迁移必须同批**。模型改动而迁移未生成，等于仓库不可运行。
3. **端点必须在同批有测试**。无测试的端点视为未交付。
4. **前端页面可以滞后于后端**，但必须在 `acceptance-checklist.md` 里显式标记为"后端已交付 / 页面待补"，
   不得静默消失——历史上 190 个 API 配 605 行前端就是这么来的。

---

## 四、越界判定（lead 在步骤 2 必须逐条检查）

以下任何一条命中即**拒绝该规格**：

- 引入 V3.0 第一期禁止清单中的组件（PostgreSQL / MySQL / Redis / Celery / RabbitMQ / Kafka / 微服务 / K8s / ES / 第二套 ORM / 第二套迁移工具）
- 金额用 float 或元存储；课时用 float
- 把所有业务状态塞进一个 `status`
- 把课程、科目、政策写死在 Python 枚举或前端
- 用一个 JSON 字段替代考勤、考试、收费、申报领域表
- 让数据库执行任意 Python / SQL / eval / 不受控 Jinja
- 覆盖已确认考勤、官方成绩、资金记录、正式报表历史
- 保存永久 OSS URL；身份证号进入 Object Key
- 编造上海各区补贴金额、退费口径、政府字段
- 在 FastAPI BackgroundTasks 中处理退款、申报等关键业务状态

## 五、交付前必跑（每个批次）

```bash
cd backend
./.venv/Scripts/python.exe -m pytest -q                    # 全量测试
./.venv/Scripts/python.exe -m ruff check .                 # 静态检查
./.venv/Scripts/python.exe -m ruff format --check .        # 格式检查
./.venv/Scripts/python.exe -m alembic upgrade head         # 空库迁移（涉及迁移时）
```
前端涉及页面时追加：`npx vue-tsc --noEmit` + `npm run build`。

---

## 六、真实性条款

1. **未完成就是未完成。** 不得用"已规划""已设计""抽象已就绪"替代"已交付"。
2. **未验证不算完成。** 执行者写完不等于交付，必须过 `verify`。
3. **不确定的业务口径必须留空并列为待确认项**，不得由执行者拍板。
4. 每个批次结束时，lead 必须如实说明：本批**做完了什么**、**没做完什么**、**下一批是什么**。
