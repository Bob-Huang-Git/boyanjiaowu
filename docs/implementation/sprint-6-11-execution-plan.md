# Sprint 6–11 分批施工计划

- **制定日期**：2026-09-23
- **代码基线**：`7f1c215`，Alembic head `d0d0739439c8`
- **当前状态**：Sprint 6 后端模型、API 与 10 条核心业务测试已完成；权限初始化、数据范围、页面和人工验收未完成
- **执行原则**：一个批次一个明确范围；模型与迁移同批；端点与测试同批；前端交付不得静默延期；每批结束运行全量门禁

## 1. 固定边界

后续工作继续使用 Python 3.12、FastAPI、SQLAlchemy 同步 Session、SQLite、Alembic、Vue 3、TypeScript、Vite 和 Element Plus。

不引入 Docker、PostgreSQL、MySQL、Redis、Celery、消息队列、微服务、Kubernetes、第二套 ORM 或第二套迁移工具。金额保持整数分，时长保持整数分钟。确认后的资金、考勤、成绩、权益、申报和报表快照只能追加修订、调整或冲正。

用户尚未确认的政策金额、部门字段、审批矩阵和真实政府模板保持可配置或留空，不在代码中编造。

> **业务决定（2026-09-23）**：政府补贴正式规则由业务方后续提供。当前不预置单价、半天/全天阈值、半天比例、上限、舍入或地区差异；政策数据保持空白。系统只保留版本化机制，并拒绝用代码默认值补齐缺失的正式政策字段。

## 2. 每批统一完成定义

每个批次必须同时满足：

1. 规格能回溯到验收清单或已确认调整。
2. 数据模型变更包含 Alembic 迁移，并验证空库升级与上一 head 升级。
3. 写接口具备组织范围、权限、幂等、乐观锁、状态转换和审计。
4. 列表在 SQL 层应用数据范围，不先查全量再由前端隐藏。
5. 新增业务端点有正向、拒绝、重复请求和越权测试。
6. 页面具备 loading、空态、错误提示、权限降级和安全返回路径。
7. 更新 `acceptance-checklist.md`、领域文档和批次记录。
8. Ruff、pytest、Alembic check、前端 typecheck 和 build 全部通过。

## 5. Sprint 7：政府申报、核定、应收与到账

### S7.1 申报模型与权益占用

- 新增 `ClaimBatch`、`ClaimSubmissionRevision`、`ClaimLine`、`ClaimLineSource`。
- ClaimBatch 表示逻辑批次，每次正式提交新建 revision。
- ClaimLineSource 明确引用 SubsidyEntitlement 和本次占用金额。
- 使用唯一约束、版本号和短事务保证所有部门累计占用不超过可申报余额。
- 测试双部门合法分摊、重复申报拒绝和并发占用。

### S7.2 退回修订与差异

- v1 退回后创建引用 v1 的 v2，禁止覆盖旧 revision。
- 保存提交摘要、内容哈希、提交人、时间和退回原因。
- API 与页面显示行级新增、删除和金额变化。

### S7.3 核定与政府应收

- 新增 `ClaimDecision`、`ClaimDecisionLine`、`ClaimAdjustment`。
- 校验申报金额等于核定、驳回和待处理金额之和。
- 仅核定金额形成 `GovernmentReceivable` 与明细。
- 支持部分通过、部分驳回、待处理和补材料。

### S7.4 到账与核销

- 新增 `GovernmentReceipt` 与 `GovernmentReceiptAllocation`。
- 一笔到账可核销多个应收，一个应收可分多次到账。
- 银行流水密文或业务幂等键防重复；撤销分配和到账冲正保留原记录。
- 状态从明细计算，不用批次级 `paid` 布尔值。

### S7.5 页面与验收

- 交付申报批次、权益占用、revision 差异、核定、政府应收、到账及核销七类页面。
- 学员和班级视角可下钻申报状态。
- 完成验收清单 P7 的 12 项测试后打 tag。

## 6. Sprint 8：政府 Excel/Word 报表中心

### S8.0 真实模板接收门

- 收集真实区县、部门、年度模板和字段说明。
- 未取得真实模板时只使用文件名和页面水印明确标记的测试模板。
- 模板来源、哈希、适用区间和审批人登记入库。

### S8.1 标准数据集与校验

- 新增报表模板、版本、适配器登记、校验规则、运行和问题模型。
- 定义只读、版本化字段字典；业务判断在数据集阶段完成。
- 校验问题能定位唯一源对象和字段，修复源数据后自动复验。

### S8.2 Excel 与 Word 适配器

- Excel 使用 openpyxl 修改原模板；Word 使用 docxtpl 和 python-docx。
- 每个复杂模板使用明确版本化 Python 适配器，不接受任意表达式。
- 适配器只处理位置、样式、分页、图片和渲染。

### S8.3 正式快照和 revision

- 冻结标准数据集、源记录版本、政策版本、模板哈希、适配器版本和输出 SHA-256。
- 退回后创建新 revision，旧文件与旧快照不可覆盖。
- 文件生成在数据库事务之外完成，前后只使用短事务。

### S8.4 黄金文件与页面

- 验证 Sheet、合并单元格、样式、打印设置、隐藏区域、公式、图片及 Word 跨页。
- 页面覆盖模板管理、校验纠错、预览、复核、正式生成和历史 revision。
- 完成 P8 十项测试后打 tag。

## 7. Sprint 9：OSS 私有附件

### S9.0 ADR-0003 和安全设计

- 先决定服务端中转与浏览器直传边界、分片阈值和本地保留策略。
- 明确 RAM 最小权限、CORS、版本控制、服务端加密、生命周期和日志脱敏。
- 不创建或修改真实云资源。

### S9.1 存储适配器与测试替身

- 实现 `LocalFakeStorage` 和 `AliyunOssStorage`，业务层只依赖 StorageBackend。
- 凭证走默认凭证链或 ECS RAM Role，禁止硬编码。
- SDK 异常转换成稳定错误码，不泄露 bucket、签名或密钥。

### S9.2 prepare/complete 上传协议

- 实现 prepare-upload、complete-upload、download-url 和 archive。
- complete 幂等，并通过 HeadObject 校验大小、类型、etag/versionId 和可用校验信息。
- PENDING、QUARANTINED、ARCHIVED 文件不能走普通下载。

### S9.3 浏览器直传和分片录屏

- 普通文件和大录屏按 ADR 走直传；录屏内容不经过 FastAPI。
- 后端控制 object key、upload_id 和允许的 part。
- 提供未完成分片和孤儿对象清理 CLI。

### S9.4 本地副本迁移与验收

- 新建 OSS 副本、校验、提升主副本、降级本地副本，失败可回滚到已验证本地主副本。
- Object key 不含姓名、证件号、手机号或原始文件名。
- 完成 P9 十项安全测试和部署配置清单后打 tag。

## 9. Sprint 11：原生 ECS 部署与最终验收

ADR-0001 优先于原始 Docker 要求。本阶段使用 Nginx、systemd、Uvicorn 单 worker 和宿主机 timer。

### S11.1 生产配置与迁移流程

- 启动前校验密钥、Cookie、目录权限、SQLite PRAGMA 和单 worker。
- migration 独立执行；执行前一致性备份，失败有明确恢复步骤。
- 数据库、WAL、附件和临时目录位于 ECS 本地持久盘，不进入仓库。

### S11.2 备份、恢复和监控

- SQLite backup API 或 VACUUM INTO；备份校验后可复制到 OSS backups 前缀。
- 做一次全量恢复演练并记录 RPO/RTO 实测。
- 完成 healthcheck、日志轮转、磁盘容量、备份失败和数据库锁告警。

### S11.3 安全验收

- 默认密码、CSRF、IDOR、跨班级/项目、文件欺骗、路径穿越、公式注入、签名泄漏、重复提交和并发退款。
- 依赖与 secret 扫描结果存档；日志抽查不含敏感明文。

### S11.4 端到端和容量验收

### S11.5 发布候选
